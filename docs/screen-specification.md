# 5. 試合一覧画面

## 表示

- アウェイチーム

## 絞り込み

- お気に入り

## 検索（日付・チーム名）

- 試合一覧の上に検索フォーム（日付・チーム名・大会・「検索」ボタン・「クリア」リンク）を置く。お気に入り表示中も表示する
- 日付（`date`、`Y-m-d`）：日本時間のその日（0:00:00〜23:59:59）にキックオフする試合。DB は UTC 保存なので、JST の範囲を UTC に変換して比較する
- チーム名（`team`、50文字以内、前後の空白は除く）：ホーム・アウェイのチームの正式名・略称・3文字コード・日本語の正式名・日本語の略称のどれかに部分一致（大文字小文字は区別しない。`%` `_` は文字として扱う）
- 大会（`competition`）：大会コード。プルダウンは日本語名の順（日本語名がないものは英語名で並べ、同じ名前のときは ID の順）。空は「すべての大会」（既定）
- `date` か `team` のどちらかが入っていたら検索モード。節／ステージの選択の代わりに「検索結果（N件）」を表示する。並びはキックオフ順、1ページ20件で、ページを移っても検索条件を保つ
- チーム名のみ（日付なし）：「今後の試合」「過去の試合」のタブ（`period=upcoming|past`、既定は今後）。今後は現在時刻以降を早い順、過去は新しい順。日付も指定したときはタブを出さず、その日の試合を早い順に表示する
- お気に入り表示中に検索したら、検索結果だけを表示する（お気に入りのブロックは出さない）。「検索をクリア」で試合一覧に戻る（お気に入りがある人はお気に入り表示に戻る）
- 0件のときは「条件に合う試合はありません。」を表示する
- 入力チェック：`date` は正しい `Y-m-d` の日付、`team` は50文字以内で、UTF-8 として正しい文字列（不正なバイト列は「チーム名に使えない文字が含まれています。」）、`competition` は存在する大会コード（検索モードのときだけ確認する。検索していないときは確認せず、存在しない大会は「該当する試合が見つかりませんでした。」になる）。不正なときはエラーメッセージを表示して検索しない。`period` が upcoming / past 以外なら upcoming とする
- 入力エラーで検索しなかったとき、入力した日付・チーム名・大会は検索フォームに残す（文字列でない値や UTF-8 として正しくない値は残さない）
- ページ番号（`page`）が最後のページより大きいときは、最後のページを表示する（0件のときは「条件に合う試合はありません。」）
- ページ送りの文言は日本語で表示する（例：「35件中 1〜20件を表示」）
- 検索していないときの大会（`competition`）・節（`match_day`）・ステージ（`stage`）に、文字列でない値（配列など）や UTF-8 として正しくない値が来たときは、指定なしとして既定（プレミアリーグ・第1節・最初のステージ）を表示する。節を空で指定したとき（`?match_day=`）も第1節を表示する

# 7. 放映店舗一覧

試合詳細画面（6）の中に表示する、その試合を放映する店舗の一覧。試合に関係なく全店舗を並べる独立した画面は設けない。
公開状態（`published`）の店舗の、公開状態の放映のみを対象とする。

## 対象

- 公開状態（`published`）の放映で、店舗が公開状態かつ削除されていないもの。
- 「有効な座席種別」は `broadcast_seat_types.is_active = true` かつ `seat_types.is_active = true` のもの。有効な座席種別が1つもない放映は出さない。

## 表示（1店舗＝1行）

- 店舗名（店舗詳細画面へのリンク）
- 所在地（都道府県・市区町村。例「東京都渋谷区」）
- 料金（有効な座席種別の最安値。「3,000円〜」の形式）
- 予約できる席数（空席状況）。合計が 0 なら席数の代わりに「満席」と表示する。
- 予約の受付状態。`reservation_start_at` / `reservation_end_at`（UTC 保存）と現在時刻を比べ、開始前なら「受付前」、終了後なら「受付終了」のバッジを席数の横に表示する。期間内、または値が null の側は制限なしとみなす。受付期間外でも一覧からは外さない。
- 「予約する」ボタン（予約画面への導線）。予約できる放映で残席が1以上のときだけ表示する。ただし、ログインユーザーがこの試合に confirmed または visited の予約を持っている場合は、どの店舗にも表示しない。
- 「予約済み」バッジと「予約内容を見る」リンク（予約詳細画面へ）。ログインユーザーが confirmed または visited の予約を持つ店舗の行に、満席・受付前・受付終了でも優先して表示する。予約した店舗が非公開・削除済みで一覧に出ない場合も、ほかの店舗の「予約する」は表示しない。cancelled / no_show の予約や、ほかのユーザーの予約は影響しない。

予約できる席数は、有効な座席種別ごとに `残席 = max(0, broadcast_seat_types.capacity − (confirmed と visited の予約の人数合計))` を求め、店舗内で合計した値とする。来店済み（visited）はキックオフ後も席を使っているので数える。cancelled / no_show の予約は数えない。

## 並び順

クエリパラメータ `sort` で切り替える。画面に切り替えリンクを置き、選択中のものが分かるようにする（`favorite` など既存のクエリパラメータは維持する）。

- `seats`：予約できる席数の多い順（既定）
- `price`：最安料金の安い順
- `name`：店舗名の順

許可リスト以外の値や未指定は `seats` として扱う（エラーにしない）。同順位は店舗名の順、店舗 ID の順で安定させる。

## 終了した試合・0件

- 試合が終了した場合は一覧を出さず、「この試合の放映は終了しました。」とだけ表示する。終了の判定は、`football_matches.status` が `FINISHED` / `AWARDED` / `CANCELLED` のいずれか、またはキックオフから3時間以上経過している場合（試合データの同期が遅れて status が古い場合のため）。
- 対象の放映店舗が0件なら「放映店舗がありません。」と表示する。

住所の詳細・Google Mapsは店舗詳細画面（8）で表示する。

## 操作

店舗詳細・予約画面へ進む。

# 8. 店舗詳細画面

URL は `/shops/{shop}`（ログイン必須）。公開状態（`published`）の店舗のみ表示し、非公開・削除済みの店舗は 404 とする。

## 表示

- 店舗名
- 店舗説明
- 住所（郵便番号・都道府県・市区町村・番地）
- 電話番号
- 営業時間（DB の値を JST の時刻としてそのまま表示する。閉店時刻が開店時刻より前なら「17:00〜翌1:00」の形式。どちらかが未設定なら表示しない）
- Webサイト（`http` / `https` の URL のみ外部リンクにする）
- Google Maps（Maps Embed API で地図を埋め込む。場所は place_id → 緯度経度 → 住所の順に指定する。API キー未設定時は「Google マップで開く」リンクを表示する）
- 座席情報（有効な座席種別の名前・説明・基本料金。試合ごとの料金・残席は放映店舗一覧（7）で表示する）
- 放映予定試合（公開状態の放映のうち、キックオフが現在より後の試合をキックオフの早い順に最大10件。キックオフは JST で表示し、試合詳細画面へリンクする）

# 9. 予約入力画面

URL は `/broadcasts/{broadcast}/reservations/create`（ログイン必須。ロールは問わない）。入口は試合詳細（7）の放映店舗一覧の「予約する」ボタンで、予約できる放映で残席が1以上のときだけ表示する。ログインユーザーがこの試合をすでに予約している（どの店舗でも confirmed または visited の予約がある）場合は、入力画面には入れず、試合詳細に戻して「この試合はすでに予約済みです。」を表示する。

予約できる放映の条件（入力・確認・確定のすべてでサーバー側で確認する）：

- 放映が公開中（`published`）、店舗が公開中かつ削除されていない
- 試合が終了していない（7 と同じ判定）
- 予約の受付期間中（`reservation_start_at` 以上 `reservation_end_at` 以下。null の側は制限なし）

満たさない場合は試合詳細に戻し、理由をメッセージで表示する。

## 表示

- 試合・キックオフ日時（JST）
- 店舗
- 座席種別ごとの 1人あたり料金・残席・1回の予約の人数上限（予約できる座席種別のみ。残席0は選べない）

## 入力

- 座席種別（必須。その放映の有効な座席種別に限る）
- 人数（必須。1 以上、座席種別の `max_people_per_reservation` 以下、残席以下）
- 備考（任意。200文字以内）

座席種別・人数を変えると合計金額を表示する（画面内の JavaScript による表示用。確定時の金額はサーバー側で計算する）。「確認画面へ」で確認画面に進む。

# 10. 予約確認画面

URL は `POST /broadcasts/{broadcast}/reservations/confirm`。入力値をサーバー側でバリデーションし、問題なければセッションに保存して表示する。この試合をすでに予約している場合は、試合詳細に戻して「この試合はすでに予約済みです。」を表示する。

## 表示

- 試合
- キックオフ日時（JST）
- 店舗
- 座席
- 人数
- 単価
- 合計金額
- 備考

## 操作

- 「予約確定」：`POST /broadcasts/{broadcast}/reservations`。入力値と確認画面で見せた単価はセッションから取り出す（リクエストから金額・人数を受け取らない）。セッションに単価がない入力（確認画面を通っていない送信）は「入力内容が見つかりません。もう一度入力してください。」と同じ扱い。
- 「戻る（入力し直す）」：入力画面に戻る。セッションの入力値が初期値になる。

予約確定は、トランザクションの中で次の順に行う。

1. 予約するユーザーの `users` の行を `lockForUpdate()` でロックする（同じユーザーが同じ試合の別の店舗へ同時に予約するのを直列化する）。続けて、その放映の `broadcast_seat_types` の行を ID 順に `lockForUpdate()` でロックする（同じ放映への同時予約・二重送信を直列化する）。
2. 予約できる放映・有効な座席種別か、受付期間中か、試合が終了していないかを再確認する。
3. 確認画面で見せた単価（サーバー側のセッションに保存した値）が、ロック後の `broadcast_seat_types.price` と同じかを確認する。違えば拒否し、「料金が変更されました。内容を確認してもう一度予約してください。」を表示して入力画面に戻す（同意していない金額で確定しない）。続けて、人数が1回の上限以下か、残席（`capacity − (confirmed と visited の人数合計)`）以下かを再確認する。
4. 二重予約の確認：同じユーザーは、同じ試合に（どの店舗でも）confirmed または visited の予約を1件までしか持てない（座席種別・店舗が違っても1件まで。cancelled / no_show は数えない。cancelled や no_show の予約があれば新しく予約できる）。拒否時のメッセージは「この試合はすでに予約済みです。」。
5. 予約を作る：`status = confirmed`、`unit_price` は確定時点の `broadcast_seat_types.price`、`total_price = unit_price × number_of_people`、`reserved_at` は現在時刻（UTC）、予約コードを発行。

確認に失敗したら予約を作らず、入力画面に戻して理由（満席になった、受付期間外、すでに予約済み など）を表示する。放映自体が予約できない場合は試合詳細に戻す。確定に成功したら、セッションの入力値を消して完了画面へリダイレクトする（再読み込みで二重に予約されない）。

### 予約コード

英大文字と数字の8桁のランダム文字列。紛らわしい文字（0, O, 1, I）は使わない。推測されにくい乱数で作り、`reservation_code` の UNIQUE 制約と重複したら作り直す。

# 12. マイページ

URL は `/mypage`（ログイン必須）。ヘッダーの「マイページ」（ログアウトの左）から開く。自分の予約だけを表示する。

## 表示

- ユーザー情報：名前とメールアドレスのみ
- 今後の予約：試合のキックオフ時刻（UTC で比較）が現在時刻以降の予約（キックオフちょうどは今後）。キックオフの早い順。0件のとき「今後の予約はありません。」
- 過去の予約：キックオフ時刻が現在時刻より前の予約。キックオフの新しい順。0件のとき「過去の予約はありません。」
- 同じキックオフの予約は、予約の ID の降順で並べる。
- 一覧からはキャンセルできない（キャンセルは予約詳細画面から行う）。
- キャンセル済みの予約も消さずに、今後・過去のどちらにも表示し、状態を「キャンセル済み」と出す。
- 予約1件ごとの表示：試合（ホーム vs アウェイ）、キックオフ（日本時間、Y/m/d H:i）、店舗名（削除済みの店舗も表示）、座席、人数、合計金額、予約状態、予約コード、予約詳細へのリンク
- お気に入りチーム：登録済みのチーム名（日本語名の順。日本語名がないものは英語名で並べ、同じ名前のときは ID の順）と、「お気に入り登録」画面へのリンク。0件のとき「お気に入りチームはまだ登録されていません。」
- ページネーションはしない。

予約状態の表示名：confirmed=予約確定、cancelled=キャンセル済み、visited=来店済み、no_show=来店なし。

# 13. 予約詳細画面

URL は `/reservations/{reservation}`（ログイン必須。ID を使い、予約コードは URL に使わない）。予約したユーザー本人だけが見られる（他人の予約・存在しない ID は 404。Policy で判定）。

## 表示

- 予約コード
- 予約状態（表示名は 12. マイページと同じ）
- 試合
- 店舗（削除済みの店舗も表示）
- 座席
- 人数
- 金額（合計金額）
- 備考（入力があるときのみ）
- 「マイページに戻る」「試合詳細へ」のリンク

## 操作

### 予約キャンセル

- キャンセルできる条件：予約した本人の予約で、状態が confirmed、かつ試合のキックオフ時刻（UTC で比較）より前であること。キックオフちょうど以降はできない。店舗の公開状態・削除、放映の公開状態・受付期間は問わない。
- 条件を満たす予約の詳細にだけ「この予約をキャンセルする」ボタンを出す。キャンセルできない予約（cancelled / visited / no_show、キックオフ以降）ではボタンを出さず、理由も表示しない。
- ボタンを押すとブラウザの確認ダイアログ「この予約をキャンセルしますか？」を出す。確認画面は作らない。
- 送信先は `PATCH /reservations/{reservation}/cancel`（ログイン必須、CSRF 必須、GET では受け付けない）。他人の予約・存在しない ID は 404。
- キャンセルすると status を cancelled、cancelled_at に現在時刻（UTC）を記録する。人数・金額などは変えない。残席は confirmed と visited の人数合計から自動的に戻り、同じ試合を再び予約できる。
- 成功したら予約詳細に戻り「予約をキャンセルしました。」を表示する（状態は「キャンセル済み」）。
- 画面を開いた後に条件を満たさなくなった場合や、リクエストを直接送った場合は、状態を変えずに予約詳細に戻り「この予約はキャンセルできません。」を表示する。
- 同時操作・二重送信に備え、予約の行をロックして条件を再確認してから更新する。

# 14. 店舗管理画面

対象：

shop_owner（アカウントは運営者が `php artisan shop-owner:create` で作る。登録画面からは作れない）

## 機能

- 店舗情報確認（実装済み）
- 店舗編集（実装済み）
- 座席管理
- 放映管理
- 予約管理

## 店舗情報（確認・編集）

URL：`/owner/shops`（一覧）、`/owner/shops/{shop}/edit`（編集）、`PUT /owner/shops/{shop}`（更新）。ヘッダーの「店舗情報」から（shop_owner のときだけリンクを表示する）。範囲は確認と編集（公開・非公開の切り替えを含む）。店舗の新規登録・削除、緯度経度・place_id の入力は作らない。

- 権限：shop_owner だけ。未ログインはログイン画面へ、shop_owner 以外は 403。他のオーナーの店舗・削除済み・存在しない店舗は 404。認可は入力の検証より先に行う。
- 一覧：自分の店舗を ID 順に表示する（削除済みは出ない。非公開も含む）。列は店名、住所（郵便番号つき）、電話番号、営業時間、公開状態（公開 / 非公開）、「編集」。0件のときは「店舗がありません。」を表示する。
- 編集できる項目と入力のルール（前後の空白は除く。空文字は null として保存する）：
  - 店名：必須、100文字以内。
  - 郵便番号：任意。「123-4567」か7桁の数字（全角は対象外）。保存は「123-4567」の形にそろえる。
  - 都道府県：任意。47都道府県のどれか（`Shop::PREFECTURES`。「東京都」のような正式名）。
  - 市区町村：任意、100文字以内。
  - 番地以降：必須、255文字以内。
  - 電話番号：任意。数字とハイフンだけ、30文字以内、数字が1つ以上あること。
  - 説明：任意、2000文字以内。
  - 開店時刻・閉店時刻：両方入力するか両方空。形式は HH:MM。同じ時刻は不可。閉店が開店より前なら翌日扱い（表示は「17:00〜翌1:00」）。保存は DB と同じ H:i:s の形。
  - Webサイト：任意。http / https の URL だけ（`javascript:` などは不可）、2048文字以内。
  - 公開状態：必須、draft（非公開）/ published（公開）。
  - 配列などの型の崩れた値は、500 にせず入力エラーにする。
- 画面に出さない・送られても使わない項目：オーナー（`user_id`）、緯度経度、`google_place_id`、削除日時。保存は検証済みの項目だけを使う。
- 公開の条件：上の入力が通れば公開できる（座席種別・放映の有無は問わない）。
- 非公開にしたとき：店舗詳細は 404、試合詳細の放映店舗一覧から消え、新しい予約ができない（`Broadcast::isReservable()`）。すでに入っている予約は有効のまま（マイページ・予約詳細で見られる）。オーナーの管理画面（予約・放映・座席）は使える。公開中の店舗を非公開にして保存するときは、ブラウザの確認ダイアログを出す。公開に戻すと、また見えて予約できる。
- 住所を変えたとき：郵便番号・都道府県・市区町村・番地以降のどれかが変わったら、緯度経度と `google_place_id` を消す（古い位置の地図が出ないよう、住所から地図を出す）。位置の入れ直しは Google Maps のタスクで行う。住所を変えずに他の項目だけ変えたときは、位置情報は残る。
- 更新したら一覧に戻り「店舗情報を更新しました。」を表示する。同時に編集されたときは、ロックせず、後から保存したものが残る。

## 座席管理（座席種別）

URL：`/owner/seat-types`（一覧）、`/owner/seat-types/create`（登録）、`/owner/seat-types/{seatType}/edit`（編集）。ヘッダーの「座席管理」から（shop_owner のときだけリンクを表示する）。範囲は一覧・登録・編集・無効化と有効化。削除は作らない（放映・予約が参照しているため）。

- 権限：shop_owner だけ。未ログインはログイン画面へ、shop_owner 以外は 403。店舗は `?shop={id}` で選ぶ（放映管理・予約管理と同じ。指定がなければ ID の小さい店舗。他のオーナーの店舗・削除済み・存在しない店舗・配列などスカラーでない値は 404。登録の POST の `shop_id` も同じ）。他店・削除済みの店舗の座席種別の編集・更新・切り替えは 404。
- 一覧：名前、説明、既定の席数、既定の料金、状態（有効・無効）、使っている放映の数（その座席種別を持つ放映の座席の件数）、「編集」「無効にする／有効にする」。並びは有効なものが先、その中は ID 順。
- 入力：
  - 名前：必須、100文字以内、店舗の中で重複しない（無効なものとも重複しない。編集では自分自身は可）。前後の空白は除く。
  - 説明：任意、500文字以内。
  - 既定の席数：必須、1〜65535。
  - 既定の料金：必須、0〜1,000,000（放映の料金と同じ）。
  - 同時登録・同時更新で名前が重複して DB の UNIQUE に当たったときも、入力画面に戻して「この名前の座席種別はすでにあります。」を出す。
- 既定の席数・料金は、放映を新しく登録するときの初期値。変えても、登録済みの放映の席数・料金は変わらない（編集画面でそれを伝える）。
- 無効にすると、放映の登録・編集で新しく選べず、どの放映でもその座席の新しい予約ができない。すでに入っている予約は有効のまま。無効にする前にブラウザの確認ダイアログを出す。有効に戻すと、また予約できる。有効・無効は、なりたい状態（`is_active`）を送って決める（二重送信しても結果が変わらない）。
- 登録・更新・有効無効の切り替えのあとは一覧に戻り、メッセージを出す。
- 放映の登録画面で有効な座席種別がないときは、座席種別の登録へのリンクを出す。

# 15. 放映登録画面

URL：`/owner/broadcasts`（一覧）、`/owner/broadcasts/create`（登録）、`/owner/broadcasts/{broadcast}/edit`（編集）。ヘッダーの「放映管理」から（shop_owner のときだけリンクを表示する）。
範囲は放映の一覧・新規登録・編集（公開・非公開の切り替えを含む）。削除は未実装。

## 権限

- shop_owner だけが使える。未ログインはログイン画面へ、shop_owner 以外（user・admin）は 403。
- 店舗の選び方は店舗予約一覧（16）と同じ。`?shop={id}` で選び、指定がなければ ID の小さい店舗。他のオーナーの店舗・削除済み・存在しない店舗は 404（登録の POST も同じ）。店舗が0件なら「店舗が登録されていません。」と表示する。
- 非公開の店舗にも登録できる（店舗が非公開なら一般ユーザーには出ない）。

## 一覧

- 「今後」「過去」のタブ（`?period=upcoming|past`、既定は今後）。キックオフ（UTC）が現在以上なら今後。今後は昇順、過去は降順。1ページ 20 件。
- 列：試合（日本語名と、その下にキックオフ（JST））、受付期間（JST。未設定は「制限なし」）、ステータス、座席（名前・席数・料金）、予約数（confirmed と visited の人数合計 / 販売席数）。
- 登録後は一覧に戻り「放映を登録しました。」を表示する。
- 各行に「編集」のリンクを出す。終了した試合（`FootballMatch::isFinished()`：終了とみなす status、またはキックオフ＋3時間を過ぎた）の放映には出さない。

## 入力

1. 大会を選ぶ（`?competition=`）。キックオフ前の試合がある大会が選択肢。
2. 試合を選ぶ（`?match=`）。その大会のキックオフ前の試合のうち、その店舗で未登録のものが選択肢。
3. 次を入力する。
   - 予約開始日時・予約終了日時（JST で入力、DB は UTC。ともに必須）。初期値は、開始が今（分単位）、終了がキックオフ＋3時間。
   - 放映ステータス（draft / published。初期値は draft）。
   - 販売する座席：店舗の有効な座席種別（`seat_types.is_active`）を一覧で出し、販売するものにチェックを付ける（1つ以上必須）。座席ごとに次を入力する。
     - 販売席数：初期値は `default_capacity`。1〜65535。
     - 料金：初期値は `default_price`。0〜1,000,000 の整数。
     - 1予約の最大人数：初期値は 4。1 以上かつ販売席数以下。さらに、料金 × 最大人数が 4,294,967,295 以下（予約の合計金額の上限）。
- 有効な座席種別が0件の店舗では「有効な座席種別がないため、放映を登録できません。」と表示する（座席の登録は画面14、未実装）。
- タイトル・開場日時・メモは入力欄を作らない（NULL のまま）。

## 検証

- 試合：キックオフ前で、終了とみなされる status（FINISHED / AWARDED / CANCELLED）ではなく、その店舗で未登録のもの。大会の選択は絞り込みのためだけで保存しない。
- 受付期間：開始 < 終了 ≤ キックオフ＋3時間（試合終了の判定と同じ。ちょうど3時間後は可）。
- 座席：その店舗の有効な座席種別の ID に限る（他店・無効な座席種別は拒否）。
- 店舗・試合・座席種別の ID はサーバー側で決めた値を設定する（リクエストの値をそのまま保存しない）。

## 流れ

`POST /owner/broadcasts` → 認可（自分の店舗か。入力の検証より先）→ 検証 → 1つのトランザクションで `broadcasts` と `broadcast_seat_types` を作る → 一覧へ。
同じ店舗・同じ試合は、検証と DB の UNIQUE の両方で防ぐ。同時登録で UNIQUE 違反になったときは 500 にせず、入力画面に戻して「この試合はすでに登録されています。」と表示する。

## 編集（`GET /owner/broadcasts/{broadcast}/edit`、`PUT /owner/broadcasts/{broadcast}`）

- 編集できるのは、受付期間・ステータス・座席。試合は変えられない（画面に表示するだけ。`shop_id`・`football_match_id` が送られても使わない）。
- 認可：放映の店舗のオーナー（shop_owner）だけ。shop_owner 以外は 403、他のオーナーの店舗・削除済みの店舗の放映・存在しない放映は 404。入力の検証より先に認可する。
- 入力項目と検証は登録と同じ（受付期間は必須で、開始 < 終了 ≤ キックオフ＋3時間。ステータスは draft / published）。
- 座席の欄：その放映にある座席（販売停止中も含む）と、まだ足していない店舗の有効な座席種別を並べる。
  - 既にある座席：今の席数・料金・最大人数・販売中かを初期値にする。「予約済み（来店済みを含む）：N人」を表示し（confirmed と visited の人数合計）、席数の下限が分かるようにする。
  - 足せる座席：座席種別の既定値を初期値にして、チェックは外しておく。チェックして更新すると、新しい `broadcast_seat_types` の行を作る。
  - エラーで戻ったときのチェックは、送信した `selected` があるものだけに付ける。
- 販売中の座席が1つ以上あること（全部の販売停止はエラー）。さらに、公開（published）にするときは、予約できる座席（販売中で、かつ座席種別が有効なもの）が1つ以上あること。無効な座席種別の座席だけを販売中に残して公開するのはエラー（「予約できる座席（座席種別が有効なもの）を1つ以上販売してください。」を座席の欄に出す。全部止めたいときは非公開にする。非公開にするときは、座席種別がすべて無効でも更新できる）。無効な座席種別の座席を販売中のまま残すこと自体は、ほかに予約できる座席があれば可。検証とサービスのロック後の両方で確認する。座席管理で座席種別を無効にしたことで予約できる座席がなくなる放映ができるのは、そのまま（制限しない）。
- 予約との関係：
  - 席数は、その座席の confirmed と visited の予約の人数合計より少なくできない（ちょうどは可）。違反したときは入力画面に戻し、席数の欄に「予約済みの人数（N人）より少ない席数にはできません。」を出す。
  - 予約がある座席も販売停止（チェックを外す）できる。`broadcast_seat_types.is_active` を false にして行は消さない。既存の予約はそのまま有効で、新しい予約だけが止まる。
  - 料金は変えられる。既存の予約の金額（`unit_price`・`total_price`）は予約時点の値のまま変わらない。
  - 予約がある放映も非公開に戻せる。一般ユーザーの一覧からは消え、既存の予約はマイページ・店舗予約一覧に残る。
  - 座席種別が無効（`seat_types.is_active = false`）になった後も、既にある座席は表示・編集できる。販売停止にするのは可。販売中に戻すのは座席種別が有効なときだけ。
- 終了した試合の放映は編集できない。編集の URL を開いたときも送信したときも、一覧に戻して「この試合は終了しているため、放映を編集できません。」を表示する。
- 流れ：認可 → 終了した試合の確認 → 検証 → 1つのトランザクションで、その放映の `broadcast_seat_types` の行を ID 順にロック（予約の確定と同じ行・同じ順番）→ ロック後に、終了した試合かどうかと席数の下限を確かめ直す → `broadcasts` と座席を更新（送られなかった既存の座席は販売停止）→ 一覧へ戻り「放映を更新しました。」を表示する。

# 16. 店舗予約一覧画面

URL：`/owner/reservations`（ヘッダーの「予約管理」から。shop_owner のときだけリンクを表示する）

## 権限

- shop_owner だけが見られる。
- 未ログインはログイン画面へ移動する。
- shop_owner 以外（user・admin）は 403。
- 他のオーナーの店舗を `?shop={id}` で指定した場合は 404（存在しない店舗・削除済みの店舗も 404）。

## 店舗の選択

- 対象はログイン中のオーナーの店舗（削除済みは除く。非公開の店舗は含む）。
- 2店舗以上ある場合は、店舗を切り替えるタブを表示する（1店舗のときは表示しない）。
- 選択は `?shop={id}`。指定がなければ ID の小さい店舗。
- 店舗が0件のときは「店舗が登録されていません。」と表示する。

## 表示範囲

- 「今後」「過去」のタブ（`?period=upcoming|past`、既定は今後）。キックオフ時刻（UTC）が現在以上なら今後、より前なら過去（マイページと同じ）。
- 試合で絞り込める（`?match={football_match_id}`）。選択肢は、選択中の店舗が放映する試合のうち、選択中のタブに当てはまるもの。既定は「すべての試合」。
- キャンセル済みの予約も表示する（「キャンセル済み」）。
- 並び順：今後はキックオフの早い順、過去は新しい順。同じキックオフは予約 ID の降順。
- 1ページ 20 件。ページを移ってもクエリ（shop・period・match）を保つ。
- 条件に合う予約がないときは「条件に合う予約はありません。」と表示する。

## 表示

- 予約コード
- ユーザー（名前のみ。メールアドレスなどは表示しない）
- 試合（ホーム vs アウェイ、キックオフ日時は日本時間）
- 座席（座席種別名）
- 人数
- 予約状態

※ 合計金額・備考は表示しない。

## 操作

予約状態の列のボタンで、お客さんの来店を記録する（来店状態の更新）。

- 更新できるのは、試合のキックオフ時刻以降（UTC で比較。ちょうどは可）だけ。キックオフ前はできない（キックオフ前に no_show にすると、試合の前に席が空いて新しく売れてしまうため）。
- 遷移：
  - confirmed → visited（来店済み）/ no_show（来店なし）
  - visited ↔ no_show（押し間違いの付け替え）
  - confirmed には戻せない。cancelled からは変えられない。今と同じ状態への変更もエラー。
- ボタン：confirmed（キックオフ後）は「来店済み」「来店なし」、visited は「来店なしに変更」、no_show は「来店済みに変更」。キックオフ前・cancelled にはボタンを出さない。押すとブラウザの確認ダイアログを出す。
- 席数との関係：キックオフ後に no_show にした席は、受付終了まで売り直される。その後で visited に付け替えると、席を使っている人数が席数を超えることがある（残席の表示は 0 のまま）。この付け替えは止めない。また、no_show の予約があるあいだに同じ試合を別の店舗で予約し、その後で no_show を visited に付け替えると、同じ試合に数える予約が2件になることがある（1試合1件の確認は新しく予約するときだけ行う）。
- 記録：visited にしたとき visited_at に現在時刻（UTC）を入れる。no_show にしたときは visited_at を NULL にする。
- 流れ：`PATCH /owner/reservations/{reservation}/visit-status`（`status=visited|no_show`）→ 認可（自分の店舗の予約だけ。他店・削除済みの店舗の予約は 404、shop_owner 以外は 403）→ 予約の行をロックして最新の状態で条件を再確認 → 更新 → 一覧（店舗・期間・試合・ページの条件を保つ）へ戻す。キャンセルとの同時操作でも、ロックにより状態は壊れない。
- メッセージ：成功は「予約 XXXXXXXX を来店済みにしました。」「予約 XXXXXXXX を来店なしにしました。」、更新できない場合は「この予約の来店状態は変更できません。」。
- ユーザー側（マイページ・予約詳細）の表示は変えない（「来店済み」「来店なし」）。

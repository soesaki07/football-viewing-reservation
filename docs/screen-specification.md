## 検索（日付・チーム名）

- 試合一覧の上に検索フォーム（日付・チーム名・大会・「検索」ボタン・「クリア」リンク）を置く。お気に入り表示中も表示する
- 日付（`date`、`Y-m-d`）：日本時間のその日（0:00:00〜23:59:59）にキックオフする試合。DB は UTC 保存なので、JST の範囲を UTC に変換して比較する
- チーム名（`team`、50文字以内、前後の空白は除く）：ホーム・アウェイのチームの正式名・略称・3文字コード・日本語の正式名・日本語の略称のどれかに部分一致（大文字小文字は区別しない。`%` `_` は文字として扱う）
- 大会（`competition`）：大会コード。プルダウンは日本語名の順（日本語名がないものは英語名で並べ、同じ名前のときは ID の順）。空は「すべての大会」（既定）
- `date` か `team` のどちらかが入っていたら検索モード。節／ステージの選択の代わりに「検索結果（N件）」を表示する。並びはキックオフ順、1ページ20件で、ページを移っても検索条件を保つ
- チーム名のみ（日付なし）：「今後の試合」「過去の試合」のタブ（`period=upcoming|past`、既定は今後）。今後は現在時刻以降を早い順、過去は新しい順。日付も指定したときはタブを出さず、その日の試合を早い順に表示する
- お気に入り表示中に検索したら、検索結果だけを表示する（お気に入りのブロックは出さない）。「検索をクリア」で試合一覧に戻る（お気に入りがある人はお気に入り表示に戻る）
- 0件のときは「条件に合う試合はありません。」を表示する
- 入力チェック：`date` は正しい `Y-m-d` の日付、`team` は50文字以内、`competition` は存在する大会コード。不正なときはエラーメッセージを表示して検索しない。`period` が upcoming / past 以外なら upcoming とする

# 7. 放映店舗一覧

試合詳細画面（6）の中に表示する、その試合を放映する店舗の一覧。試合に関係なく全店舗を並べる独立した画面は設けない。
公開状態（`published`）の店舗の、公開状態の放映のみを対象とする。

## 対象

- 公開状態（`published`）の放映で、店舗が公開状態かつ削除されていないもの。
- 「有効な座席種別」は `broadcast_seat_types.is_active = true` かつ `seat_types.is_active = true` のもの。有効な座席種別が1つもない放映は出さない。

## 表示（1店舗＝1行）

- 店舗名（店舗詳細画面へのリンク）
- 所在地（都道府県・市区町村。例「東京都渋谷区」）
- 料金（有効な座席種別の最安値。「3,000円〜」の形式）
- 予約できる席数（空席状況）。合計が 0 なら席数の代わりに「満席」と表示する。
- 予約の受付状態。`reservation_start_at` / `reservation_end_at`（UTC 保存）と現在時刻を比べ、開始前なら「受付前」、終了後なら「受付終了」のバッジを席数の横に表示する。期間内、または値が null の側は制限なしとみなす。受付期間外でも一覧からは外さない。
- 「予約する」ボタン（予約画面への導線）。予約できる放映で残席が1以上のときだけ表示する。ただし、ログインユーザーがこの試合に confirmed の予約を持っている場合は、どの店舗にも表示しない。
- 「予約済み」バッジと「予約内容を見る」リンク（予約詳細画面へ）。ログインユーザーが confirmed の予約を持つ店舗の行に、満席・受付前・受付終了でも優先して表示する。予約した店舗が非公開・削除済みで一覧に出ない場合も、ほかの店舗の「予約する」は表示しない。cancelled / visited / no_show の予約や、ほかのユーザーの予約は影響しない。

予約できる席数は、有効な座席種別ごとに `残席 = max(0, broadcast_seat_types.capacity − confirmed の予約の人数合計)` を求め、店舗内で合計した値とする。cancelled / no_show / visited の予約は数えない。

## 並び順

クエリパラメータ `sort` で切り替える。画面に切り替えリンクを置き、選択中のものが分かるようにする（`favorite` など既存のクエリパラメータは維持する）。

- `seats`：予約できる席数の多い順（既定）
- `price`：最安料金の安い順
- `name`：店舗名の順

許可リスト以外の値や未指定は `seats` として扱う（エラーにしない）。同順位は店舗名の順、店舗 ID の順で安定させる。

## 終了した試合・0件

- 試合が終了した場合は一覧を出さず、「この試合の放映は終了しました。」とだけ表示する。終了の判定は、`football_matches.status` が `FINISHED` / `AWARDED` / `CANCELLED` のいずれか、またはキックオフから3時間以上経過している場合（試合データの同期が遅れて status が古い場合のため）。
- 対象の放映店舗が0件なら「放映店舗がありません。」と表示する。

住所の詳細・Google Mapsは店舗詳細画面（8）で表示する。

## 操作

店舗詳細・予約画面へ進む。

## 表示

- 店舗名

- 電話番号

- Webサイト（`http` / `https` の URL のみ外部リンクにする）

# 9. 予約入力画面

URL は `/broadcasts/{broadcast}/reservations/create`（ログイン必須。ロールは問わない）。入口は試合詳細（7）の放映店舗一覧の「予約する」ボタンで、予約できる放映で残席が1以上のときだけ表示する。ログインユーザーがこの試合をすでに予約している（どの店舗でも confirmed の予約がある）場合は、入力画面には入れず、試合詳細に戻して「この試合はすでに予約済みです。」を表示する。

予約できる放映の条件（入力・確認・確定のすべてでサーバー側で確認する）：

- 放映が公開中（`published`）、店舗が公開中かつ削除されていない
- 試合が終了していない（7 と同じ判定）
- 予約の受付期間中（`reservation_start_at` 以上 `reservation_end_at` 以下。null の側は制限なし）

満たさない場合は試合詳細に戻し、理由をメッセージで表示する。

## 表示

- 試合・キックオフ日時（JST）
- 店舗
- 座席種別ごとの 1人あたり料金・残席・1回の予約の人数上限（予約できる座席種別のみ。残席0は選べない）

## 入力

- 座席種別（必須。その放映の有効な座席種別に限る）
- 人数（必須。1 以上、座席種別の `max_people_per_reservation` 以下、残席以下）
- 備考（任意。200文字以内）

座席種別・人数を変えると合計金額を表示する（画面内の JavaScript による表示用。確定時の金額はサーバー側で計算する）。「確認画面へ」で確認画面に進む。

# 10. 予約確認画面

URL は `POST /broadcasts/{broadcast}/reservations/confirm`。入力値をサーバー側でバリデーションし、問題なければセッションに保存して表示する。この試合をすでに予約している場合は、試合詳細に戻して「この試合はすでに予約済みです。」を表示する。

## 表示

- 試合
- キックオフ日時（JST）
- 店舗
- 座席
- 人数
- 単価
- 合計金額
- 備考

## 操作

- 「予約確定」：`POST /broadcasts/{broadcast}/reservations`。入力値はセッションから取り出す（リクエストから金額・人数を受け取らない）。
- 「戻る（入力し直す）」：入力画面に戻る。セッションの入力値が初期値になる。

予約確定は、トランザクションの中で次の順に行う。

1. 予約するユーザーの `users` の行を `lockForUpdate()` でロックする（同じユーザーが同じ試合の別の店舗へ同時に予約するのを直列化する）。続けて、その放映の `broadcast_seat_types` の行を ID 順に `lockForUpdate()` でロックする（同じ放映への同時予約・二重送信を直列化する）。
2. 予約できる放映・有効な座席種別か、受付期間中か、試合が終了していないかを再確認する。
3. 人数が1回の上限以下か、残席（`capacity − confirmed の人数合計`）以下かを再確認する。
4. 二重予約の確認：同じユーザーは、同じ試合に（どの店舗でも）confirmed の予約を1件までしか持てない（座席種別・店舗が違っても1件まで。cancelled / visited / no_show は数えない。cancelled の予約があれば新しく予約できる）。拒否時のメッセージは「この試合はすでに予約済みです。」。
5. 予約を作る：`status = confirmed`、`unit_price` は確定時点の `broadcast_seat_types.price`、`total_price = unit_price × number_of_people`、`reserved_at` は現在時刻（UTC）、予約コードを発行。

確認に失敗したら予約を作らず、入力画面に戻して理由（満席になった、受付期間外、すでに予約済み など）を表示する。放映自体が予約できない場合は試合詳細に戻す。確定に成功したら、セッションの入力値を消して完了画面へリダイレクトする（再読み込みで二重に予約されない）。

### 予約コード

英大文字と数字の8桁のランダム文字列。紛らわしい文字（0, O, 1, I）は使わない。推測されにくい乱数で作り、`reservation_code` の UNIQUE 制約と重複したら作り直す。

# 12. マイページ

URL は `/mypage`（ログイン必須）。ヘッダーの「マイページ」（ログアウトの左）から開く。自分の予約だけを表示する。

## 表示

- ユーザー情報：名前とメールアドレスのみ
- 今後の予約：試合のキックオフ時刻（UTC で比較）が現在時刻以降の予約（キックオフちょうどは今後）。キックオフの早い順。0件のとき「今後の予約はありません。」
- 過去の予約：キックオフ時刻が現在時刻より前の予約。キックオフの新しい順。0件のとき「過去の予約はありません。」
- 同じキックオフの予約は、予約の ID の降順で並べる。
- 一覧からはキャンセルできない（キャンセルは予約詳細画面から行う）。
- キャンセル済みの予約も消さずに、今後・過去のどちらにも表示し、状態を「キャンセル済み」と出す。
- 予約1件ごとの表示：試合（ホーム vs アウェイ）、キックオフ（日本時間、Y/m/d H:i）、店舗名（削除済みの店舗も表示）、座席、人数、合計金額、予約状態、予約コード、予約詳細へのリンク
- お気に入りチーム：登録済みのチーム名（日本語名の順。日本語名がないものは英語名で並べ、同じ名前のときは ID の順）と、「お気に入り登録」画面へのリンク。0件のとき「お気に入りチームはまだ登録されていません。」
- ページネーションはしない。

予約状態の表示名：confirmed=予約確定、cancelled=キャンセル済み、visited=来店済み、no_show=来店なし。

# 13. 予約詳細画面

URL は `/reservations/{reservation}`（ログイン必須。ID を使い、予約コードは URL に使わない）。予約したユーザー本人だけが見られる（他人の予約・存在しない ID は 404。Policy で判定）。

## 表示

- 予約コード
- 予約状態（表示名は 12. マイページと同じ）
- 試合
- 店舗（削除済みの店舗も表示）
- 座席
- 人数
- 金額（合計金額）
- 備考（入力があるときのみ）
- 「マイページに戻る」「試合詳細へ」のリンク

## 操作

### 予約キャンセル

- キャンセルできる条件：予約した本人の予約で、状態が confirmed、かつ試合のキックオフ時刻（UTC で比較）より前であること。キックオフちょうど以降はできない。店舗の公開状態・削除、放映の公開状態・受付期間は問わない。
- 条件を満たす予約の詳細にだけ「この予約をキャンセルする」ボタンを出す。キャンセルできない予約（cancelled / visited / no_show、キックオフ以降）ではボタンを出さず、理由も表示しない。
- ボタンを押すとブラウザの確認ダイアログ「この予約をキャンセルしますか？」を出す。確認画面は作らない。
- 送信先は `PATCH /reservations/{reservation}/cancel`（ログイン必須、CSRF 必須、GET では受け付けない）。他人の予約・存在しない ID は 404。
- キャンセルすると status を cancelled、cancelled_at に現在時刻（UTC）を記録する。人数・金額などは変えない。残席は confirmed の人数合計から自動的に戻り、同じ試合を再び予約できる。
- 成功したら予約詳細に戻り「予約をキャンセルしました。」を表示する（状態は「キャンセル済み」）。
- 画面を開いた後に条件を満たさなくなった場合や、リクエストを直接送った場合は、状態を変えずに予約詳細に戻り「この予約はキャンセルできません。」を表示する。
- 同時操作・二重送信に備え、予約の行をロックして条件を再確認してから更新する。

# 16. 店舗予約一覧画面

URL：`/owner/reservations`（ヘッダーの「予約管理」から。shop_owner のときだけリンクを表示する）

## 権限

- shop_owner だけが見られる。
- 未ログインはログイン画面へ移動する。
- shop_owner 以外（user・admin）は 403。
- 他のオーナーの店舗を `?shop={id}` で指定した場合は 404（存在しない店舗・削除済みの店舗も 404）。

## 店舗の選択

- 対象はログイン中のオーナーの店舗（削除済みは除く。非公開の店舗は含む）。
- 2店舗以上ある場合は、店舗を切り替えるタブを表示する（1店舗のときは表示しない）。
- 選択は `?shop={id}`。指定がなければ ID の小さい店舗。
- 店舗が0件のときは「店舗が登録されていません。」と表示する。

## 表示範囲

- 「今後」「過去」のタブ（`?period=upcoming|past`、既定は今後）。キックオフ時刻（UTC）が現在以上なら今後、より前なら過去（マイページと同じ）。
- 試合で絞り込める（`?match={football_match_id}`）。選択肢は、選択中の店舗が放映する試合のうち、選択中のタブに当てはまるもの。既定は「すべての試合」。
- キャンセル済みの予約も表示する（「キャンセル済み」）。
- 並び順：今後はキックオフの早い順、過去は新しい順。同じキックオフは予約 ID の降順。
- 1ページ 20 件。ページを移ってもクエリ（shop・period・match）を保つ。
- 条件に合う予約がないときは「条件に合う予約はありません。」と表示する。

## 表示

- 予約コード
- ユーザー（名前のみ。メールアドレスなどは表示しない）
- 試合（ホーム vs アウェイ、キックオフ日時は日本時間）
- 座席（座席種別名）
- 人数
- 予約状態

※ 合計金額・備考は表示しない。

## 操作

- confirmed
- visited
- no_show

などの状態更新。（未実装。表示のみ実装済み）

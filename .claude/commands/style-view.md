# style-view

あなたはこのLaravelプロジェクトの**フロントエンド担当**です。

このプロジェクトでは、ユーザーがBladeビューの表示ロジック（`@foreach` / `@if` / 変数バインディングなど）とコントローラを書き、
あなたがその見た目（CSS）と軽微な操作性（JS）を仕上げる、という役割分担で進めています。

対象ファイル: `$ARGUMENTS`

`$ARGUMENTS`が空の場合は、作業を始める前にどのファイルを対象にするか確認してください。

---

## 参照する設計の基準

以下を必ず確認し、既存のトーンと一貫性を保ってください。

- `resources/css/app.css`の`@theme`（`pitch-*`, `gold-*`などのテーマカラー定義）
- `resources/views/layouts/app.blade.php`（共通レイアウト。ヘッダー・フッター・全体の配色トーン）
- 全体のデザイン方向性:「スタジアム/エネルギッシュ」（ピッチの深緑 + ゴールドのアクセント。詳細は`resources/views/matches/index.blade.php`を実例として参照してよい）

---

## やること

1. 対象ファイル（`$ARGUMENTS`）を読み、既存のBladeロジック（ループ・条件分岐・変数名・フォームのフィールド名やaction）を把握する。
2. Tailwindのユーティリティクラスを追加・調整し、上記の設計基準と一貫したスタイルにする。
3. 見た目のためだけに必要な最小限のラッパー要素（例: グリッド用の`<div>`）は追加してよい。
4. 簡単な操作性のためのJS（`onchange="this.form.submit()"`のような、Bladeに直接書ける範囲のインラインJS）は追加してよい。複雑な処理（Ajax通信、状態管理など）が必要そうな場合は、実装を進めずユーザーに相談する。
5. 共通レイアウト（`layouts/app.blade.php`）やテーマカラー（`app.css`の`@theme`）への追記が必要な場合（新しいナビ項目、既存に無い色が必要 等）は、既存の色・構造を壊さない範囲で追記してよい。
6. 完了したら、`routes/web.php`を確認し、対象ビューに対応するルート（URL）を探せた場合は`curl`で実際に200が返るか確認する。ルートが特定できない、またはログイン必須などで確認できない場合は、その旨をユーザーに伝えて手動確認を依頼する。

---

## 絶対に変更しないこと

- `@foreach` / `@if` / `@forelse`などの制御構造そのもの（追加・削除・条件の変更をしない）
- 変数名・データの参照先（例: `$footballMatch->homeTeam->name`）
- フォームの`name`属性・送信先（`action`）・HTTPメソッド
- コントローラ・モデル・ルートなど、PHPのロジック全般

これらに変更が必要だと感じた場合は、自分で直さずユーザーに報告してください。

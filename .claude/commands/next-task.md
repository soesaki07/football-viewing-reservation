## あなたが行うこと

上記のルール・仕様に加えて、実際のプロジェクト構成（`app/`, `routes/`, `database/migrations/`,
`tests/` など）をRead/Glob/Grepで確認したうえで、以下の順番で日本語で報告してください。

1. **現状整理**：現在どこまで実装されているか（モデル・マイグレーション・コントローラ・ルート・
   サービス・Artisanコマンド・テストの実装状況）を簡潔に整理する。
2. **仕様との差分**：docs/の仕様（テーブル定義・機能一覧・画面仕様）と現在の実装を比較し、
   まだ実装されていない部分・矛盾している部分を洗い出す。
3. **次のタスクを1つだけ決定**：「次のPull Requestとして適切な大きさ」を基準に、次に着手すべき
   タスクを**1つだけ**選ぶ。複数のタスクを並べて提示しない。
4. **理由**：なぜ数ある未実装項目の中でそのタスクを次にやるべきなのかを説明する
   （依存関係・リスク・学習効果などの観点から）。
5. **必要な知識**：実装に必要になるLaravel/PHP/DB/API等の知識を説明する
   （該当する場合のみ。例：Eloquentのリレーション、トランザクション、Carbon、Httpファサード、
   フォームリクエストによるバリデーション 等）。
6. **大まかな手順**：完成コードは書かず、処理の流れ・考え方をステップ単位で説明する。
7. **関係するクラスの役割**：必要であれば、これから作成・修正する可能性のある
   Controller / Service / Model / Request / Command / Test などについて、それぞれが
   どういう役割を持つべきかを説明する（コードは書かない）。

## 厳守事項

- **完成コードを書かない**。ヒント・方針・考え方の説明にとどめる。
- **ファイルの作成・編集は一切行わない**（Edit/Writeツールを使用しない）。
- 一度に大量のタスクを提示せず、必ず1つのタスクに絞る。
- 説明はすべて日本語で行う。
